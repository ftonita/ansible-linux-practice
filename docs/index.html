😰 Проблема: серверов становится много

Один сервер настроить руками — легко. Пятьдесят — уже боль.

🔁
Одни и те же команды на каждом сервере
→ потерянное время
🐛
Забыл шаг, опечатался
→ серверы получаются разными
📓
Знания «в голове» админа
→ никто не знает, как это настроено
🔥
Сервер упал
→ восстановление «по памяти»
Snowflake servers — «снежинки»: каждый уникален и поэтому хрупок.
💡 Идея. Описать нужное состояние один раз в виде кода и применять его автоматически — это и делает Ansible.

🧩 Что такое Ansible

Открытый инструмент автоматизации от Red Hat: настройка серверов, установка ПО, деплой и оркестрация — одним описанием на YAML.

🚫🤖

Agentless

Ничего ставить на серверы не нужно — только SSH и Python.
📝

Declarative

Описываем что должно быть, а не как это сделать.
🔄

Idempotent

Повторный запуск безопасен: уже настроенное не меняется.
👀

Читаемость

YAML понятен даже без опыта программирования.
Применение: пакеты, пользователи, конфиги, обновления, деплой, облака и сеть.

Ansible подключается по SSH, выполняет модули на серверах и убирает за собой. Никаких постоянных агентов.

🔍 Пример 1: Inventory и проверка связи

Шаг 1. Описываем серверы — inventory.ini

inventory.ini 
[web]
web-1.example.com
web-2.example.com

[db]
db-1.example.com

Шаг 2. Одна команда на все серверы

терминал 
$ ansible all -i inventory.ini -m ping
…нажмите «Запустить»

Так же можно запускать разовые команды: ansible web -m command -a "uptime" — сразу на всей группе.

📜 Пример 2: Первый playbook

nginx.yml 
- name: Настройка веб-серверов
  hosts: web
  become: true          # права root
  tasks:
    - name: Установить nginx
      ansible.builtin.apt:
        name: nginx
        state: present

    - name: Запустить и включить автозапуск
      ansible.builtin.service:
        name: nginx
        state: started
        enabled: true
терминал
$ ansible-playbook -i inventory.ini nginx.yml
…нажмите «Запустить playbook»

Запусков: 0

Идемпотентность: запустите второй раз — всё станет ok. Менять уже нечего.
