# Фундамент и забор: базовая настройка сервера

**`base.yml`**

```yaml
- name: Часовой пояс
  community.general.timezone:
    name: Europe/Moscow

- name: Базовые утилиты
  ansible.builtin.apt:
    name: [htop, curl, git]
    state: present
    update_cache: true

- name: Открыть SSH, HTTP и HTTPS
  community.general.ufw:
    rule: allow
    port: "{{ item }}"
    proto: tcp
  loop: ["22", "80", "443"]

- name: Остальное по умолчанию закрыто
  community.general.ufw:
    state: enabled
    policy: deny
```

**🖥️ Сервер = земельный участок**

| Сущность | Что это и зачем |
|---|---|
| Часовой пояс `Europe/Moscow` | Часы на стене: логи и cron-задачи живут по одному времени. |
| Пакеты — инструменты в сарае | Всё, что понадобится при работе на сервере. |

**🧱 Firewall — забор с калитками ufw**: открыто **22** (SSH), **80** (HTTP), **443** (HTTPS); остальное закрыто. Политика **deny**: закрыто всё, кроме явно открытых калиток.

> 💡 **Аналогия.** Прежде чем строить дом, размечают участок, завозят инструменты и ставят забор. С сервером так же: это делается **первым и одинаково везде**.

<details><summary>🎤 Заметки лектора</summary>

Первый кирпичный пример: то, что делают на любом сервере в первую очередь. Пролистать стрелкой 4 шага: при каждом шаге подсвечивается задача и соответствующая ей часть «участка».

Обратить внимание: `loop` позволяет положить один и тот же кирпич три раза с разными параметрами. И модули здесь из разных коллекций: community.general и ansible.builtin. К этому вернёмся на слайде про коллекции.

Порядок важен: сначала открываем 22, потом включаем deny. Иначе можно закрыть дверь перед собственным носом и потерять SSH.

</details>
