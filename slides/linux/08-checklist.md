# Первые 15 минут нового сервера

Порядок важен: каждый шаг готовит почву для следующего и **не даёт запереть самого себя снаружи**.

- [ ] 🔄 Обновиться: `apt update && apt upgrade`
- [ ] 👤 Создать своего пользователя и добавить в `sudo`
- [ ] 🔑 Положить SSH-ключ и **проверить вход в новом окне** — ⚠️ до отключения паролей
- [ ] 🚪 Запретить root и пароли, проверить `sshd -t`
- [ ] 🧱 `ufw allow OpenSSH`, потом `ufw enable` — ⚠️ именно в таком порядке
- [ ] 🛡️ Поставить fail2ban
- [ ] 🔦 `ss -tulpn` и выключить всё лишнее

**`site.yml — всё это одной ролью`**

```yaml
- hosts: all
  become: true
  roles:
    - hardening   # обновления, users, ssh,
                  # ufw, fail2ban, лишние сервисы
```

⏱️ Руками, один сервер: **~15 минут** и надежда, что ничего не забыли. Ansible, любое число серверов: **одна команда** `ansible-playbook site.yml`.

> 💡 **Аналогия.** Каждый пункт чек-листа — кирпичик. Сложите их в роль `hardening`, и **любой новый сервер** получит ту же защиту за один запуск.

🙌 Вопросы? [← Часть 1: Ansible](../ansible/)

<details><summary>🎤 Заметки лектора</summary>

Пройтись по чек-листу и отметить пункты. Акцент на двух ловушках: отключать пароли только после проверки входа по ключу и включать ufw только после allow SSH. Обе ошибки приводят к потере доступа к серверу.

Финальная мысль: всё, что сегодня делали руками, складывается в одну роль Ansible. Это и есть связь двух частей курса: понимаем Linux и автоматизируем его.

Домашнее задание: написать роль hardening из задач этой лекции и прогнать её на чистой виртуальной машине дважды. Второй запуск должен быть полностью ok.

</details>
