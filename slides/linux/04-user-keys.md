# Свой пользователь с sudo и вход по ключу

**`Руками · сервер и ноутбук`**

```bash
# на сервере: пользователь + право sudo
sudo adduser anna
sudo usermod -aG sudo anna
# на своём ноутбуке: пара ключей
ssh-keygen -t ed25519 -C "anna@laptop"
# положить публичный ключ на сервер
ssh-copy-id anna@203.0.113.10
# проверить: пускает без пароля
ssh anna@203.0.113.10
```

**`Ansible · users.yml`**

```yaml
- name: Пользователь с правом sudo
  ansible.builtin.user:
    name: anna
    groups: sudo
    append: true
    shell: /bin/bash
- name: Публичный ключ anna
  ansible.posix.authorized_key:
    user: anna
    key: "{{ lookup('file', 'keys/anna.pub') }}"
```

| Сущность | Что это и зачем |
|---|---|
| anna + группа sudo | Работаем под своим именем. Права root берём точечно через `sudo`, и каждый вызов попадает в журнал. |
| Приватный ключ | `~/.ssh/id_ed25519` Ключ от квартиры: только у вас, никому не отдавать. |
| Публичный ключ | `id_ed25519.pub` Замок: можно повесить на сколько угодно серверов. |

<details><summary>🎤 Заметки лектора</summary>

Сначала создаём своего пользователя. Работать под root опасно: любая опечатка выполняется с полными правами, а в журнале не видно, кто именно что сделал.

Аналогия с ключами: приватный ключ — ключ от квартиры, публичный — замок. Замок можно раздать и повесить на любые двери, а ключ всегда остаётся у вас.

Пройти рукопожатие по шагам. Главное: по сети не передаётся ни пароль, ни приватный ключ, поэтому подбирать нечего. Ключ ed25519 — современный и короткий, его и рекомендуем.

Обязательно проверить вход по ключу в новом окне терминала, прежде чем отключать пароли на следующем слайде.

</details>
