# Обновления — заплатки на уже известных дырах

**`Руками · терминал`**

```bash
# 1. обновить список пакетов
sudo apt update
# 2. что можно обновить?
apt list --upgradable
# 3. поставить обновления
sudo apt upgrade -y
# 4. нужна перезагрузка (новое ядро)?
ls /var/run/reboot-required
sudo reboot
```

**`Ansible · updates.yml`**

```yaml
- name: Обновить список пакетов
  ansible.builtin.apt:
    update_cache: true
    cache_valid_time: 3600
- name: Поставить обновления
  ansible.builtin.apt:
    upgrade: safe
- name: Нужна ли перезагрузка?
  ansible.builtin.stat:
    path: /var/run/reboot-required
  register: reboot_flag

- name: Перезагрузить, если нужно
  ansible.builtin.reboot:
  when: reboot_flag.stat.exists
```

| Сущность | Что это и зачем |
|---|---|
| apt update — свежий каталог | Скачивает список: какие версии вышли и какие уязвимости в них закрыты. Сам ничего не ставит. |
| apt upgrade — сами заплатки | Ставит новые версии пакетов. `upgrade: safe` в Ansible ничего не удаляет. |
| reboot-required — нужен перезапуск | Новое ядро и некоторые библиотеки начинают работать только после перезагрузки. |

> 💡 **Аналогия.** Об уязвимости пишут в бюллетене безопасности, чтобы все поставили заплатку. Но этот бюллетень **читают и взломщики**: не обновился — значит, оставил дверь, о которой знают все.

<details><summary>🎤 Заметки лектора</summary>

Первое действие на новом сервере — обновиться. Образ, из которого создан сервер, мог собираться месяцы назад, и в нём уже есть известные уязвимости.

apt update и apt upgrade — разные команды: первая обновляет каталог, вторая ставит пакеты. Частая ошибка новичков — сделать только update.

Ползунок: чем дольше сервер не обновляется, тем дольше открыто окно, в которое могут пролезть по опубликованной инструкции. В Ansible это три задачи, которые безопасно запускать хоть каждый день. Для продакшена стоит упомянуть пакет unattended-upgrades, который ставит патчи безопасности автоматически.

</details>
