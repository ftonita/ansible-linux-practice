# Роль — готовый блок из кирпичиков

Задачи, шаблоны, переменные и handlers для одной темы упаковывают в **роль**. Дальше дом собирается из ролей, а не из отдельных кирпичей.

**`roles/postgresql/`**

```text
roles/postgresql/
├── tasks/main.yml       # что делать (кирпичики)
├── handlers/main.yml    # реакции на изменения
├── templates/           # бланки конфигов
├── defaults/main.yml    # настройки по умолчанию
└── meta/main.yml        # от чего зависит роль
```

**`site.yml — весь проект на одном экране`**

```yaml
- hosts: db
  roles: [common, users, firewall, postgresql]

- hosts: web
  roles: [common, users, firewall, nginx, docker]
```

> 💡 **Аналогия.** Модульный дом: кухню привозят целиком, с техникой и инструкцией. Нужна такая же в другом доме — заказываете **тот же блок**.

- `nginx` — вход и вывеска
- `docker` — квартиры-контейнеры
- `postgresql` — хранилище
- `users` — пропуска и ключи
- `firewall` — забор с калитками
- `common` — фундамент: время, пакеты, обновления

<details><summary>🎤 Заметки лектора</summary>

До этого мы складывали кирпичи по одному. В реальном проекте задач сотни, поэтому их группируют в роли по смыслу: всё про PostgreSQL — в роль postgresql.

Переключить web / db справа. Блоки common, users и firewall общие: они переиспользуются везде. Это главный выигрыш: написали один раз, применяем на всех типах серверов.

site.yml — вся инфраструктура на одном экране. Новый человек открывает этот файл и сразу понимает, как устроен проект.

</details>
